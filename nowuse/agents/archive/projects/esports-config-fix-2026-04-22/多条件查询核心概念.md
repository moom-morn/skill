# 多条件查询核心概念

## 一、基本结构

**搜索条件配置对象（SearchCondition）：**
```javascript
{
  label: '显示标签',              // 必传
  key: 'database_field_name',     // 必传
  compType: 'select|input|date|range',  // 必传
  
  // 可选配置
  more: true,                     // 多选
  search: 'queryHero',            // 动态查询接口名
  searchSportId: 4,               // 游戏ID (1=LOL, 2=CSGO, 3=DOTA, 4=KOG)
  precise: 1|2,                   // 1=模糊(__startswith), 2=精确(__in)
  showPrecise: true,              // 显示模糊/精确切换
  parameterKey: true,             // 不添加后缀（保持原key）
  parameterValue: true,           // 用opts[i].value作为参数key
  parameterSuffix: '__gte',       // 手动添加后缀
  opts: [],                       // 下拉选项
  defaultValue: '',               // 默认值
  disabled: false,                // 禁选
  filterable: true                // select本地搜索
}
```

---

## 二、compType 四种组件

| 类型 | 说明 | 示例 |
|------|------|------|
| **select** | 下拉框 | `{compType: 'select', opts: [{label:'选项1', value:1}]}` |
| **input** | 输入框 | `{compType: 'input', precise: 1, rules: 'int'}` |
| **date** | 日期 | `{compType: 'date', parameterSuffix: '__gte'}` |
| **range** | 范围 | `{compType: 'range', minCount: 0, maxCount: 100}` |

---

## 三、参数拼接关键字段

| 字段 | 作用 | 场景 |
|------|------|------|
| `precise` | 添加查询后缀 | input组件：1(__startswith模糊) 或 2(__in精确) |
| `parameterKey` | 不添加后缀 | ID、UID等不需要后缀的字段 |
| `parameterValue` | 用value作为参数key | VIP筛选等特殊映射（选了"月会员"→ vip_expire_at__gte） |
| `parameterSuffix` | 手动添加后缀 | 日期范围查询（__gte、__lte） |
| `search` | 触发动态查询 | **值必须来自 resourceTextJump 中的 key**（见第四章说明） |

## 四、项目文件组织

```
searchKey/compKey/matchBall/
├── lol.js (LOL配置)
├── csgo.js (CSGO配置)
├── dota.js (DOTA配置)
└── kog.js (KOG配置)

searchTopKey/topKeyItem/matchBall/
├── lol.js → ["match_time", "id", "team_id", ...]
├── csgo.js
├── dota.js
└── kog.js
```

**关键差异：**
- `searchKey/*.js` → 完整配置对象：`{lolMatchList: {match_time: {...}, id: {...}}}`
- `topKeyItem/*.js` → 数组列表：`{lolMatchList: ["match_time", "id", ...]}`
- topKeyItem中的字段必须已在searchKey中定义过

## 五、电竞游戏映射

| 游戏 | ID | 通用字段（search:支持） | 特有字段（opts:静态） |
|------|----|---------|---------| 
| **LOL** | 4 | tournament_id(competition)、stage_id(stage)、team_id(team)、player_id(player)、match_id(match) | hero_id、equipment_id |
| **CSGO** | 2 | tournament_id(competition)、stage_id(stage)、team_id(team)、player_id(player)、match_id(match) | map_id、weapon_id |
| **DOTA** | 3 | tournament_id(competition)、stage_id(stage)、team_id(team)、player_id(player)、match_id(match) | hero_id、item_id |
| **KOG** | 4 | tournament_id(competition)、stage_id(stage)、team_id(team)、player_id(player)、match_id(match) | hero_id、item_id |

**说明：** 
- 通用字段括号内为 search 值（来自 resourceTextJump）
- 特有字段因 resourceTextJump 中无定义，应使用 opts 静态选项或后端提供的接口

## 六、快速对照表

### 常用组件配置模板

```javascript
// 下拉单选（动态查询 - search值来自resourceTextJump）
{ label: '赛事', key: 'tournament_id', compType: 'select', search: 'competition', searchSportId: 1 }

// 下拉多选
{ label: '队伍', key: 'team_id', compType: 'select', more: true, search: 'team', searchSportId: 1 }

// 日期（含快捷时间）
{ label: '比赛时间', key: 'match_time', compType: 'date', defaultValue: setClickShortcutsTime(3) }

// 输入框+模糊/精确
{ label: '队伍名称', key: 'team_name', compType: 'input', precise: 1, showPrecise: true }

// 输入框+不加后缀
{ label: 'UID', key: 'id', compType: 'input', parameterKey: true, rules: 'int' }

// 范围选择
{ label: '积分范围', key: 'score', compType: 'range', minCount: 0, maxCount: 100 }

// 下拉静态选项（无搜索接口时）
{ label: '英雄', key: 'hero_id', compType: 'select', more: true, filterable: true,
  opts: [{label: '盲僧', value: 1}, {label: '蛮子', value: 2}, ...] }
```

## 七、参数转换示例

### 最终查询参数格式

| 配置 | 输入值 | 最终参数 |
|------|--------|---------|
| `precise: 1` | "SKT" | `{search_cond: {team_name__startswith: "SKT"}}` |
| `precise: 2` | "1,2,3" | `{search_cond: {extra_data__in: [1,2,3]}}` |
| `parameterKey: true` | 123 | `{search_cond: {id: 123}}` |
| `parameterSuffix: '__gte'` | 时间戳 | `{search_cond: {match_time__gte: 时间戳}}` |
| `parameterValue: true`<br>value:"vip_expire_at__gte" | 选择"月会员" | `{search_cond: {vip_expire_at__gte: 现在}}` |

## 八、核心约定

1. **searchKey中的key必须与后端字段一致**
2. **searchSportId映射：** LOL(1), CSGO(2), DOTA(3), KOG(4)
3. **search参数值必须来自 `/src/utils/dict/common.js` 中 `resourceTextJump` 的 key 值**
   - 有效值：`match`, `competition`, `stage`, `team`, `player`, `user`, 等
   - 无效值：`queryXXX`, `searchXXX`, `hero`, `equipment`, `map`, 等（这些字段在resourceTextJump中未定义）
   - **如果search对应的搜索组件不存在，则删除search字段改用opts静态选项**
4. **多选数据(more:true)** → 后端接收数组或逗号分隔字符串
5. **模糊/精确切换** → precise字段值由前端修改__startswith/__in后缀
6. **topKeyItem数组** → 只列出要在Top Bar显示的字段名，其他自动折叠

## 九、实现流程（三步）

  xxxxMatchList: {

## 十、search 参数详细说明

**重要发现：** search 参数的值必须是 `/src/utils/dict/common.js` 中 `resourceTextJump` 常量的 key 值。

### resourceTextJump 定义的有效值

```javascript
// 电竞搜索可用的 search 值
"match"       // 比赛
"competition" // 赛事  
"stage"       // 阶段
"team"        // 队伍
"player"      // 队员
"user"        // 用户
"expert"      // 预测号
"post"        // 帖子
// ... 更多见 common.js
```

### ❌ 无效的 search 值（不要使用）

```javascript
"queryHero"        // ❌ resourceTextJump 中不存在
"queryEquipment"   // ❌ 
"queryMap"         // ❌ 
"queryTeam"        // ❌ 应该是 "team"
"queryTournament"  // ❌ 应该是 "competition"
```

### 修正示例

```javascript
// 错误
{ label: "赛事", key: "tournament_id", search: "queryTournament" }

// 正确
{ label: "赛事", key: "tournament_id", search: "competition" }
```
